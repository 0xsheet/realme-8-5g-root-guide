# دليل روت realme 8 5G

[English](README.md) · [خطوات التنفيذ الكاملة](docs/guide.ar.md) · [المحاولات والنتيجة](docs/case-study.md)

هذا الريبو يوثّق تجربة روت ناجحة على **realme RMX3241 / RE513CL1، Android 13،
البناء RMX3241_11_F.12، منطقة LATAM** باستخدام **Magisk 30.7**.
يحتوي الشرح والأوامر والتعاريف وسكربتات تنزيل الأدوات وفحص الجهاز والنسخ والتعديل والتحقق.

**ما ثبت على الهاتف الأصلي:** أقلع Android بعد إعداد Magisk وإعادة التشغيل، وأعطى
`su -c id` النتيجة `uid=0(root)` بتاريخ 26 أكتوبر 2026.
**حدود الاختبار:** السكربتات المعاد تنظيمها هنا خضعت لفحوص آلية ومحلية؛ لم نعد تنفيذ
دورة الكتابة كاملة على هاتف آخر. نجاح التجربة الأصلية لا يثبت توافق كل النسخ.

الريبو ليس تطبيق روت بضغطة واحدة. أوامر الكتابة ترفض الموديل أو البناء أو المنطقة
المختلفة. إذا جهازك مختلف اقرأ [دليل التكييف لجهاز آخر](docs/other-devices.md)، ولا
تغيّر اسم الموديل في الملف فقط لتجاوز الفحص.

## البداية

1. اقرأ [الدليل الكامل](docs/guide.ar.md)، خصوصًا حدود النسخة الاحتياطية ومسح البيانات.
2. استخدم Linux x86_64 وكيبل بيانات سليم، وافصل الهواتف الأخرى.
3. انسخ صورك وملفاتك الشخصية بشكل مستقل؛ فتح القفل مسح بيانات الهاتف الأصلي.
4. الملفات المعدلة تُنشأ من نسخ هاتفك نفسه. لا ننشر boot أو preloader جاهزًا للتفليش.

```bash
git clone https://github.com/0xsheet/realme-8-5g-root-guide.git
cd realme-8-5g-root-guide
python3 -m venv --without-pip .venv
python3 -m pip --python .venv/bin/python3 install -r requirements.txt
.venv/bin/python3 -m rootguide fetch-tools
.venv/bin/python3 -m rootguide doctor
```

أمر `fetch-tools` ينزّل الأدوات من المصادر المسجلة في `assets.lock.json`، يتحقق من
بصمات الملفات ولقطات Git ومرحلتي DA، ويجهز حاوية DA المستخدمة في التجربة. لا يرسل
أي أمر للهاتف. أمر `doctor` يقرأ معلومات الجهاز فقط ويخفي الرقم التسلسلي ببصمة محلية.

## البرامج وAPK والتعاريف

| المكوّن | النسخة المختبرة / دوره |
|---|---|
| ADB وfastboot | Platform-Tools 36.0.0؛ الاتصال وفتح البوتلودر |
| Antumbra | 2.0.0؛ اتصال MediaTek عبر libusb مع Carbonara |
| MTKClient | لقطة مثبتة؛ مصدر حاوية DA ومكتبة قراءة التحقق |
| DA لـOPLUS MT6833 2025 | مرحلتان من موارد GeekFlashTool، مع التحقق من SHA256 |
| أداة Shocked-Cat | تعديل علم دخول fastboot في preloader الأصلي |
| Magisk APK | 30.7 رسمي؛ تعديل boot وإدارة الروت |
| قاعدة udev | صلاحية منافذ MediaTek على Linux؛ ليست تعريف Windows |

كل الأدوات تنزل داخل `local/tools/` وتبقى محليًا. ملفات الجهاز والنسخ وسجلاته داخل
`local/` أيضًا، ولا تدخل في Git. حقوق وتراخيص الأدوات الأصلية موضحة في
[THIRD_PARTY.md](THIRD_PARTY.md).

## التسلسل

فحص الهوية ← نسخة خاصة للأقسام ← تعديل boot على الهاتف نفسه ← تعديل وصول fastboot
في preloader الأساسي مع حفظ الكود الموقّع ← فتح البوتلودر القياسي وتأكيد مسح البيانات
على الهاتف ← إثبات unlocked من Android ← كتابة boot عبر DA ← قراءة الملف كاملًا
لإثبات التطابق ← إعداد Magisk وإعادة التشغيل ← إثبات UID 0.

```bash
.venv/bin/python3 -m rootguide backup            # عرض الخطة فقط
.venv/bin/python3 -m rootguide backup --execute  # إعادة تشغيل + قراءة الأقسام
```

لا تتابع من هذا المثال مباشرة إلى التفليش؛ أكمل المراحل المرتبة في الدليل. الكتابة
تحتاج خطة محفوظة و`--execute --confirm RMX3241`. كتابة boot تحتاج كذلك إثبات فتح
البوتلودر. لا يوجد أمر تلقائي لفتح القفل أو مسح البيانات أو تعديل vbmeta أو إعادة القفل.

## الفحوص والمشاركة

```bash
make check
```

الفحوص لا تكتب على هاتف متصل. لا تنشر ملفات NVRAM/NVDATA أو أرقام الأجهزة أو نسخك
الخاصة في Issues. هذا الدليل يشرح المسار وحدوده وطرق تشخيص الفشل، ولا يدّعي دعم جميع
إصدارات realme أو جميع معالجات MediaTek.
